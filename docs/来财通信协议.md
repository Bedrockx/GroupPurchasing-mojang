# 来财通信协议 v1

本协议与[项目设计](来财项目设计.md)配套。A 是服务端，B 是莫酱桌面端，C 是来财脚本。下表中的角色按实际认证连接和本机绑定目录确定。

## 身份和传输

跨设备沿用 Socket.IO 的 `message` 事件。网络和本地文件使用相同的 JSON 结构。例如大号报名时发送以下消息。

```json
{"type":"laicai","version":1,"op":"seat-ready","messageId":"m_01","roomName":"来财一队","payload":{"role":"big","clientId":"pc_1","laicaiVersion":"1.0.0","uid":"100000001","gameName":"甲"}}
```

每条消息必有以上六个外层字段。标识符只用 ASCII 字母、数字、下划线或连字符，长度 1–128。游戏 UID 使用 9–10 位十进制字符串。报名时 `host` 表示小号侧主用户，`big` 表示大号。服务端将登录账号、客户端持久 `clientId` 和当前 Socket 绑定，授权只由该连接发送相应席位的回报。重连必须按同账号、同客户端重新绑定。小号 `workerId` 是房间内约定的逻辑标识。

房间参数为 `roomType:"laicai"` 和 `laicai:{bigCount,worldUids,allowMissing,timeoutSeconds}`。大号数为 1–3，世界计划为 1–45 个唯一 UID，允许缺人默认 false，中途等待默认 120 秒（有效整数 1–86400）。准备阶段另受项目设计中的分段与整次上限约束。

### 消息上下文

| 字段组 | 字段 | 含义 |
| --- | --- | --- |
| T | taskId | 整场任务。角色和席位从发车时固定的名单恢复。 |
| W | worldUid, worldAttemptId | 指定一个世界和当前尝试，同一 UID 再尝试使用新的 ID。 |
| K | workerId, slotId, slotGeneration | 小号所在多用户，位置为 1 或 2，占用代次从 1 起。 |
| N | rosterVersion | 当前世界有效名单版本，从 1 起。名单缩减保留已经确认的成功结果。 |
| S | seatId | 本次指令涉及的大号席位。小号侧的 S 表示本次允许进入的队员。 |
| R | routeSeq | 本世界拟执行或正在执行的完整路线序号，从 1 起。 |

B 从 A 接受授权时保存其 messageId，向 C 派发时使用独立 messageId 并保存映射。C 结果的 `replyTo` 指向本地指令，B 上报 A 时改为对应的网络指令 ID。重复发同一条逻辑消息始终使用原 messageId。带上下文的指令回复须回显同一上下文，异步成员观察通过 W、K、N 关联。接收端根据实际连接检查作用范围，拒绝已撤销的席位、阶段、代次或授权。

## 操作及负载

| 操作 | 发出方及阶段 | 作用域 | payload 必要内容或动作 |
| --- | --- | --- | --- |
| seat-ready / seat-withdraw | B 集合 | 房间 | 报名带 role,clientId,laicaiVersion。big 另带 uid,gameName。host 另带 workers（每项 workerId,uids，最多三个 UID）。撤销带 clientId。 |
| task-start | A 满员时 | T | role,seatId,laicaiVersion,roster,worldUids,allowMissing,timeoutSeconds。roster 由大号的 seatId,uid,gameName 组成。 |
| executor-ready / heartbeat | B 或 C 经 B | T | role,laicaiVersion。心跳另带 source（client 或 executor）、stage，可附所在尝试。host 的脚本应带 W、K。主用户恢复后持续轮询未释放且正在准备、待接待或接待中的槽位，按任务、世界、多用户和槽位代次转发新鲜心跳，已回收输入仍可关联该心跳。 |
| prepare-world / worker-stage | A 授权，host 分段回报 | TWK | 准备指令带房间 timeoutSeconds 及 deadline、prepareUntil（毫秒时间戳）。小号按房间时限等待放行、现场复核与清场；准备阶段沿用各段截止时间及整次上限。B 给旧任务新发的现场指令也携带房间时限。分段回报 replyTo 关联原授权，stage 为 starting、game、switching、verifying 或 failed。失败提供 reason，slotReusable:true 表示本机已确认可以安全复用。重复阶段不续期。 |
| world-ready | host 核验完成 | TWK | observedUid,exactReads。observedUid 等于 worldUid，连续两次或以上精确读取且游戏可接人。 |
| open-admission / admission-opened | A 指定唯一开放世界，host 确认 | TWKN | 开放携带 roster。白名单生效后确认。 |
| admit-seat / seat-armed | A 指定当前申请者，host 回报 | TWKNS | 授权携带 uid,gameName。回报携带稳定且无歧义的 members 基线，每项含 seatId,position，首席基线为空。基线缺少已入场席时，host 继续观测，A 等待该席重现或按房间超时规则处理。 |
| join-world / join-result | A 授权，big 回报 | TWNS | 正常入场成功回报 status=joined、fromSingle:true、position（2–4）。降员造成双方席号不一致时，A 可另发 positionOnly:true。big 连续两次读到相同客人席号后回报 status=position、position。该操作只读取现场。两种授权失败均回报 status=failed 和 reason。 |
| world-members | host 连续观察队伍时 | TWKN | stable,ambiguous,members。每项含 seatId,position。入场观测的 replyTo 指向本席 admit-seat，降员或恢复现场时引用当前观测授权。A 在给 host 的 admit-seat、roster-update 中携带同一世界尝试内递增的 observationSeq，B 和 C 按此序号识别晚到的旧指令。出现未知访客时 ambiguous=true。A 结合本席入场结果、申请前基线及当前成员图判断，后到的不确定观测清除之前的入场证据。 |
| route-release / run-route | A 向 B 授权，B 向 C 派发 | TWNSR | 执行指定序号。控制接收在追踪期间仍可工作。 |
| route-result | big 在整条路线结束时 | TWNSR | status 为 success、await-team、failed、canceled、empty。success 与 await-team 都须带布尔 isLast，并已独立确认本席仍在本轮世界、已执行完整路线、抵达目标及稳定脱战。success 另须带本地击败证据 evidence（reward 或 combat-transition）。await-team 表示个人条件满足、需队友提供同轮击败证据。失败或取消带 reason。 |
| roster-update / cancel-route | A 改名单，A 或 B 取消追踪 | TWN / TWNSR | 前者带 roster，后者带 reason。取消只影响指定指令。 |
| leave-world / seat-left | A 下达退场，big 回报 | TWNS | 同一任务、房间、未关闭的世界尝试、目标 UID 和席位的退场授权可在名单升版后执行。确认退回单人时按原授权回报 single:true。 |
| check-clear / world-cleared | A 要求清场，host 回报 | TWKN | 小号关闭放行，连续稳定观测为零后回报 stable:true,memberCount:0。 |
| release-world / cancel-attempt | A 授权释放，A 或 host 撤销尝试 | TWK | 撤销带 reason，不能代替清场确认。准备失败后无法确认安全时，A 隔离该位置并向 B 发 cancel-attempt。B 的 applied 回执带 slotReusable，A 仅在尝试、代次匹配且值为 true 时重新启用该位置。 |
| state-request / state-snapshot | B 重连请求，A 下发 | 房间 | 请求带 clientId，恢复已有任务时同时带 taskId 及已知 seatId。运行快照含任务阶段、当前和预备世界、有效名单、路线进度、截止时间及本席待办。撤销房权后，原账号、客户端与任务匹配时，A 返回带 cleanupOnly 的原席快照，仅下发本席取消、退场、清场、释放和终止授权。归档后 task 为 null，terminal 中的 commandId 是发给本席的原 task-end 编号。 |
| task-end | A 整场终止或完成 | T | status、reason、worldResults（逐 UID 的结果）。 |
| ack | 接收方 | 原消息作用域 | replyTo 引用原 messageId。status 为 received、started、applied 或 rejected。rejected 带 reason，事务尚未写入时另带 retryable:true。B 发给 A 的可靠控制回执（started、applied、rejected）附本机 clientId。A 成功提交后回一次 applied，B 据此清队列，这份服务端回执无需再应答。 |

## 本地邮箱与恢复

当执行端离线错过终止指令，B 将对应的本机脚本目录隔离。操作员确认旧脚本已停止、大号已回单人或小号世界已清场后，可以在原账号的报名面板解除隔离。主进程核对本机客户端、账号、房间、角色、目录和任务归属，向 `mailbox/state/end-<taskId>.json` 写入持久终止标记，再回收本房间该任务残余的输入。C 下次启动时先处理此标记、拒绝旧任务的重放，再接新任务。

A 在同一 taskId、worldAttemptId、routeSeq 内保留第一份真实击败证据，直到切换路线或世界。只有至少一席具备证据且全部有效席位的个人条件已完成才放行。已确认的证据在同轮缩减名单后保留。全员 await-team 时进入 waiting-evidence，并从此时按房间中途时限开始收证。同席在期限内可以引用原授权将 await-team 更新为有独立证据的 success，过期或前一条路线的回报不能放行。小号世界为空包另行记为 empty。

每份来财的邮箱位于脚本目录的 `mailbox/`。B 写入 `in/<messageId>.json`，同目录临时写完再改名发布。C 写 `out/<messageId>.json` 成功后再写 `out/<messageId>.ready.json`，检查两次写入的返回值。B 仅枚举以 `.ready.json` 结尾的标记，由标记定位正文。两个 Windows 多用户绑定各自脚本目录。收件先持久登记再回执，已处理消息只重发已知回报。B 将 C 的回报持久排入其网络待发队列后才回收本地事件，A 确认后再清网络队列。断线时已经执行的动作可以收尾，后续放行等快照与现场一致后才继续。

入场或降员复核期间，主用户断线或 A 重启即清除缓存成员图。主用户恢复时，A 保留大号原申请和已有的入场回报。尚待基线时向小号重新发 admit-seat，已授权大号申请或正在核实降员时重新发 roster-update。C 收到新编号后重新采样，即使现场与断线前相同也回报。A 只接受新授权下与目标 UID、确认加入权限一致的稳定观测，维持原截止时间。同一恢复请求重传沿用本次观测授权。

任务状态文件替换或终态归档写入失败时，A 回滚内存事务，发出的 rejected 带 retryable:true。B 保留原信封与 messageId，退避后或重连时补发。没有 retryable:true 的业务拒绝是最终裁决。可靠控制回执同样等待提交确认，心跳和 received 阶段通知无需进入持久待发队列。整场结束后，原账号和 clientId 仍能用归档中的原授权及回执编号确认最后的释放、收尾。补发不会再次切号、执行路线或放行。

降员后，A 保留同轮已确认的击败证据及仍在名单内各席的完成进度。保留席位已经开始的路线仍可用原授权回报，须同时匹配本任务、世界尝试、席位、路线序号和原消息编号。被移出席位的迟到进度不能推进同步。A 用新名单定向发送取消与退场，仍接受该席的清理回执。C 按任务、世界、席位、路线及原授权取消，名单升版不妨碍结束原追踪。小号复核目标 UID、放行权限及完整的在场名单，确认异常席已经离场后才继续。房间结束时按持久终态或重连快照处理客户端占用，原代次释放后才能向该位置派新多用户。

## 中途异常与终态

1. A 接收路线的第一份 started 后开始计执行期限，之前按接单期限等待。同一授权的重复 started 不会续期。已完成本地路线的席位等待队友时不计路线执行超时。客户端与游戏执行端分别发送心跳，心跳不能延长命令期限。活性观察窗口取房间时限与 15 秒中的较大者，以容纳正常的 5 秒心跳间隔。
2. A 降员时向相关席位和小号发新版 roster-update，payload 含 roster、removed、reason。小号按原有全员身份识别现场，并以本次 roster-update 为 replyTo 报新版本 world-members。稳定观测须附本世界的 observedUid、admissionMode=confirm，包含全部已入场的有效席，且已移出者须离场。如果正在申请的席位保留，A 在给 host 的更新中附 applicant，允许继续放行且现场可额外包含该席。A 在给该大号的更新中附尚待回报的 retainedJoin（原 messageId、rosterVersion），B 对应到本地指令编号，C 即使先收到新名单也能处理指定原授权。A 在新名单下重新核对该席的入场结果和小号的成员席号后放行下一步。大号退出与小号观察分别回报。保留席位仍在执行的 route-release 可以用原名单版本回报，A 仅接受同席、同尝试、同序号及同原授权的回执。未收到足以排除异常席的证据时，服务端不能放下一条。
3. 移出席位恢复单人待命后发不含旧世界的 executor-ready，payload 使用 role、laicaiVersion、single:true。恢复只影响后续世界。等待有效席位为零的恢复期限届满时结束任务。末条标记冲突到期终止。全员均已抵达却没有击败证据时，允许缺人的房间将该世界记为 unproven 后退场，严格房终止。
4. A 在安全清场或隔离处置完成后持久保存终态并释放房间。未清场时不发 release-world，终态携带 unsafeWorlds（每项有世界 UID、世界尝试及完整多用户位置代次）。主用户必须保留未确认位置的本地隔离。离线客户端凭原登录账号、clientId 和之前的 taskId 请求 state-request，A 以 state-snapshot.payload.terminal 返回归属于该客户端的终态与隔离明细。持有原任务锁的 B 收到快照拒绝后只处理收尾，并限频查询原任务。原 task-end 先于快照到达也可启动本地收尾；执行端确认或超时记录隔离后才解锁。日常定时重启延后至全部活动任务结束，意外重启从已确认任务状态和原截止时间恢复。

主用户可在转发 `release-world` 时加入 `payload.retire:true`。小号完成已清场世界的释放并退出本次执行循环后回 `ack applied`。仍有本多用户的 UID 时，默认只关闭当前世界并保留待命。若下一代槽位要交给其他 Windows 用户，B 先向刚释放的旧目录发本地 `retire-worker`（T、最近已释放的 W/K），等原小号 `applied` 后才启动新多用户 BAT。该动作允许原多用户稍后为同一任务的新尝试重新启动。B 仅把仍需收尾的执行端纳入整场退出确认。

小号准备失败时，B 上报 `worker-stage`，其中 `stage:"failed"` 并附 `reason` 及 `slotReusable`。已确认未启动、位置仍安全或撤销已经安全完成才可为 true。结果不明时为 false，A 隔离位置并下发针对原 W/K 的 `cancel-attempt`。B 核对小号已停止后，以该网络命令为 `replyTo` 回 `ack`，其中 `status:"applied",slotReusable:true`。无法确认时保留 false。正常轮换以 `release-world` 的 `applied` 为准，旧代次的回报不能释放新代次。

任务阶段依次为集合、准备、入场、路线、退场、释放，最后以完成或终止结束。预备世界可与在役世界并行。入场超时从本席获准申请开始，路线接单时间从授权开始，执行时间从 started 开始，完成等待其他队员时停止本席执行倒计时。A 持久保存授权、名单、完成记录和截止时间后再广播。身份或上下文错误直接拒绝，迟到的消息不得续期、切号、推进或取消下一条路线。
