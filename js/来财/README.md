# 来财

来财由莫酱房间发车。一次集合 1–3 个大号客户端和 1 个小号侧主用户客户端，依次处理最多 45 个小号世界。大号和小号侧主用户可在不同设备。小号侧主用户在本机用 BAT 启动最多两组并行 Windows 游戏会话。

## 建房与安装

1. 管理员在“新增房间”选择房间类型“来财”，填写大号人数、世界 UID 和中途等待秒数。UID 可用空格、逗号或换行分隔。每个 UID 在计划中只出现一次。向相应莫酱账号分配房间权限。
2. 需要允许中途减员时，勾选“允许中途缺人继续”。此设置只影响发车后的异常处置。首次仍须配置的大号和小号侧主用户全部在线并就绪。中途等待默认 120 秒，可根据路线耗时调整。
3. 在每个大号和每个小号 Windows 用户的 BetterGI 中，把整个脚本目录安装为 `User/JsScript/来财`。确保 `manifest.json`、`main.js`、`settings.json`、`assets/`、`routes/` 都位于该目录中。所有执行端安装相同来财版本。大号 BetterGI 需要支持下文的单次追踪取消接口。
4. 分别在各游戏会话建立包含来财 JS 的 BetterGI 一条龙配置。大号设角色 `big` 并选择本场路线包，每个小号 Windows 用户设角色 `host`。每个会话使用自己的脚本目录和本地账号资料。小号侧主用户需要对各个来财目录的 `mailbox/` 有读写权限。

## 报名和启动

| 操作方 | 设置 |
| --- | --- |
| 每名大号 | 在自己的莫酱桌面客户端配置本机 BetterGI 目录，登录后从房间信息打开“来财房间报名”。选房间和“大号”，填本账号的实际 UID、游戏内昵称及上述一条龙名称，点“就绪并参与”。 |
| 小号侧主用户 | 在主用户自己的莫酱客户端“命令白名单文件夹”中点“管理”，加入本机存放启动 BAT 的目录。在“来财房间报名”选择“小号侧主用户”，对每个实际 Windows 多用户点“添加多用户”。 |
| 每个多用户配置行 | 填一个唯一编号（字母、数字、下划线或连字符）和它负责的 1–3 个 UID，点“选择来财目录”，指向该用户实际安装的脚本目录，再选择与它对应的白名单 BAT。所有行覆盖房间世界计划后，点“就绪并参与”。 |

BAT 应在对应的 Windows 用户会话内启动其 BetterGI、原神及已配好的小号来财一条龙。主用户配置每个 BAT 在本机的真实位置。大号客户端和服务端通过逻辑编号与 UID 协调，无需获取 BAT 路径，也无需访问其他设备上的目录。

例如，多用户甲管理三个 UID，乙也管理三个 UID。首次发车后，甲准备接待时，乙可在自己的游戏窗口预切下一个 UID。预备端保持“不允许加入”。只有服务端指定开放当前世界后，小号才切到“确认后可加入”，逐席批准大号申请。当前世界退场且确认清空后，甲才能切换账号或释放位置。主用户可在报名面板查看两个位置的阶段和隔离状态。集合期间用“关闭参与”撤销报名。

## 小号切换

如果当前已经登录目标小号，来财直接复核 UID 和联机界面。需要切号时，在该多用户本地的 `account` 目录配置它负责的账号。以下两种方式任选其一。

- **选择已登录账号**　将账号选择列表中仅标识目标账号的截图保存为 `account/<UID>.png`。脚本会打开账号列表、点击匹配的条目并进入原神。此方式优先。
- **使用账号密码**　将目标 UID 的登录信息写入 `account/accounts.json`。该文件仅由当前游戏会话读取，示例使用虚构数据。

```json
{
  "100000001": { "account": "测试账号", "password": "测试密码" }
}
```

账号图片及账号文件需在本机配置。首次运行会创建目录。一次准备要在主界面连续精确读到目标 UID 两次，并实际打开联机界面，才能向主用户报告世界就绪。出现登录验证、无法识别的界面或持续读不到目标 UID 时，按准备期限报告失败，由服务端和主用户轮换。

## 大号路线与战斗

各大号在自己的脚本设置中选择相同路线包。传奇三线依次执行拳王、瓶子、曼巴草。前两条传奇只执行拳王和瓶子。传奇与小怪在三条传奇后增加渌华池小怪。首条使用参考路线的起点，其余路线使用参考配置的传送点。主路线 JSON 保留原作者、坐标和全部战斗动作。白芙图标命中时先执行原辅助追踪“强制黑芙”。当前四条原始路线均没有水下标签。

大号的 BetterGI 需要采用支持单次取消的 `pathingScript.runFile(path, cts.Token)` 接口。每个客户端使用自身 BetterGI 地图追踪的战斗配置和队伍，路线内的 `fight` 与 `combat_script` 保留原意。来财每次执行仅启用一次原版 AutoPick。

每名大号都须执行本条完整路线，并连续两次确认自己在终点附近、处于客人席位且画面中未见敌人等级提示。若在终点附近观察到新增的“角色经验”，来财回报 `success` 和击败证据。尚未看到奖励时先回报 `await-team`，在追踪结束后的 7 秒内继续观察，最迟到本条路线超时为止。期间识别到奖励且现场仍符合条件，就用原路线授权补报一次 `success`。收到下一条路线、取消、移出名单、退场或任务结束指令时，停止本条观察。

服务端收齐有效席位的本地完成回报，并取得同一世界、同一路线的击败证据后放行下一条。全员只有空现场时继续限时等待。定位失败或仍在战斗的席位不能借队友的证据跳过自己的路线。实机识别待在对应队伍和联机状态下验收。

## 中断与解除隔离

短暂断线后，以原莫酱账号和客户端重连。服务端发送原任务快照，客户端核对未确认的指令和结果。一个预备多用户启动或切号失败时，它名下尚未处理的 UID 会随该多用户跳过，已确认的其他世界进度保留。

若旧任务终止时无法确认大号退场、小号清场或旧执行端安全停止，报名面板会列出隔离的脚本目录。先在对应 Windows 用户现场确认旧来财已停止。大号应已回单人，小号应已关闭放行并确认世界内没有访客。随后在原账号、原客户端点击该目录的“核对并解除隔离”并确认。客户端持久记录旧任务终态并回收它的残留指令，其他目录各自处理。

小号执行端收到清场未确认的终态后，也会在自己的脚本目录保存隔离。其他莫酱客户端复用该目录、重启来财或改为大号角色时，仍须等待原任务解除隔离。解除后可以接收新的授权，已拒绝的指令维持原结果。

## 待实机验收

- 用一个大号和两个小号世界完整执行一次，核对真实 UID、F2 权限、实际入场、战斗所得、退回单人及清场。
- 在两个真实 Windows 多用户下并行运行，确认主用户读写正确目录、后台截图和输入各自独立，预切或预备端失败时当前世界继续。
- 跨设备用三个大号执行至少两条路线，确认快者真实待命、慢者可以使用同轮团队击败证据、超时取消只结束指定追踪，之后仍能退场。
