# 更新履历

## 2.7.1

### 改动

- **房主**：`enterCount >= maxEnterCount` 之后的 20s 死睡，改为「最后一次同意后静默 7s 倒计时」。倒计时结束做一次人数检查，不足再 1s × 2 重试；仍不足则按实际人数回填 `enterCount`。该块实测耗时 26.2s → 约 5~7s。
- **队员**：申请提交后的等待窗口由 20s 改为 3.2~4.2s（±1s 抖动），使申请间隔落在 13~15s。
- **README**：联机群号更新为 `1109232869`。

### 未改动

Y 轮询节奏、开局基线、10 分钟超时、checkpoint 机制、模板匹配去重 + OCR 兜底、踢人逻辑（`runGroupPurchasing()`）、强迫症模式判定语义。

### 实测依据（BGI 日志 + 联机配对日志）

- 原 20s 块总耗时：26.22 / 26.24 / 26.25s（三次会话一致）
- `findTotalNumber`：3.23s
- `waitForMainUI`（点允许 → 回主界面）：4ms ~ 0.5s
- 队员申请前奏（F2 → 搜索 → 点申请）：7.2~8.1s；原慢路径 30.5s
- 房主 Y 轮询周期：4.25~4.35s
- 申请有效期：下界 > 5.06s（成功接受过 5.06s 的申请），上界未知

### 已知限制

- 双方同步启动时，前两次申请仍会落在开局基线盲区（本次未改基线）；
- 申请 10 秒冷却未实测，队员侧窗口按保守假设设计；
- 人数不足时每轮都会调一次 `findTotalNumber`（约 3.2s），缺人状态下的有效轮询周期会拉长到约 7.5~11s。
